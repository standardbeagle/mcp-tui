CLI mode is activated by passing a subcommand after the connection flags. The
subcommands are `tool`, `resource`, `prompt`, `server`, `capabilities`,
`verify`, and `conform`.

```bash
mcp-tui [connection-flags] <subcommand> [args]
```

## Tools

```bash
# list available tools
mcp-tui --cmd npx --args "@modelcontextprotocol/server-everything,stdio" tool list

# describe one tool
mcp-tui ... tool describe echo

# call a tool with key=value args
mcp-tui ... tool call echo message='hello'
```

## Resources

```bash
mcp-tui ... resource list
mcp-tui ... resource get 'file:///example.txt'   # alias: read
mcp-tui ... resource templates                    # URI templates
mcp-tui ... resource complete 'file:///{path}' path=doc
```

## Prompts

```bash
mcp-tui ... prompt list
mcp-tui ... prompt get my-prompt
mcp-tui ... prompt execute my-prompt --arg key=value   # -a for short
mcp-tui ... prompt complete my-prompt topic=go
```

## Server introspection

```bash
mcp-tui ... server            # name, version, protocol
mcp-tui ... capabilities      # negotiated capabilities as JSON
```

## Conformance and probes

`verify` runs behavior probes; `conform` runs the full scenario matrix. Both
are covered in [Conformance testing](/mcp-tui/guides/testing/).

```bash
mcp-tui verify http://localhost:8000/mcp
mcp-tui conform --report-junit conform.xml http://localhost:8000/mcp
```

## Argument coercion

Strings are passed verbatim. Numeric, boolean, and JSON-shaped values are coerced based on the tool's input schema:

```bash
# auto-coerced
mcp-tui ... tool call sum a=1 b=2
mcp-tui ... tool call enabled flag=true
mcp-tui ... tool call query filter='{"limit":10}'
```

Coercion is driven entirely by the tool's input schema: a value is parsed as
the type the schema declares for that key (string, number, integer, boolean,
object/array as JSON), falling back to the raw string when the schema gives no
type. There is currently no per-argument type override — if a server's schema
is wrong, the coercion follows it.

## Exit codes

| Code | Meaning |
|------|---------|
| 0 | Success |
| 1 | Any failure |

mcp-tui exits `1` on every error — connection failures, invalid usage,
tool/protocol errors, a failing `verify` probe or `conform` scenario, or a
tool-layer error surfaced by `--strict-output` / `--strict-errors`. There are
no distinct per-class codes. Read stderr for the human-readable classification.

See [Automation & CI](/mcp-tui/guides/automation/) for pipeline patterns.
